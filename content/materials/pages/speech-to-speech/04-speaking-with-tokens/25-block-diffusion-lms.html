Block diffusion language models

A plain autoregressive model writes one token at a time, which is slow but easy to stream. A fully masked model (previous section) fills a whole clip in a few passes, which is fast but cannot start talking before the clip is planned. Block diffusion sits between the two: it writes the speech one block at a time, left to right, and fills all the tokens inside each block together.

Think of a crossword for each sentence. You never leave a sentence half done before moving on, but within one sentence you fill the easy squares first and let those answers help with the hard ones.

How it works

For one block:

  1. Start with the block fully masked; the model sees the text, the voice prompt, every finished block and the blanks.
  2. The model predicts a token and a confidence for every blank at once.
  3. Keep the most confident predictions and leave the rest blank (confidence-based unmasking).
  4. Repeat with the kept tokens as extra context, until no blanks remain or an early-stop rule says the block is good enough.
  5. Store the finished block in the KV cache (see Streaming encoders) and move to the next block.

Training. Take real speech tokens, hide a random share, and ask the model to fill the blanks. Models in this family start from a pretrained text LLM and change its attention step by step, from causal to bidirectional to block-causal: tokens inside a block see each other, while every block sees only earlier blocks. Some recipes also replace a few tokens with wrong ones instead of blanking them (mask-and-replace), so the model learns to work with a noisy context.

Systems to know

  • Luna-TTS has a full form that fills the whole token grid in a fixed number of parallel passes, and a Realtime form that is autoregressive over blocks of 32 codec frames (1.28 seconds) and denoises each block in parallel. The Realtime form reports a real-time factor (RTF) of 0.0240 (audio about 40 times faster than it plays) and 41.6 ms to the first block.
  • DLLM-TTS runs block discrete diffusion over codec tokens; a 0.6B model trained on 20K hours reports a real-time factor of 0.15 and competitive zero-shot results.
  • Chatterbox-Flash fine-tunes an existing autoregressive TTS decoder into a block-diffusion decoder, with streaming kept. OmniVoice applies the masked-diffusion idea to whole clips, mapping text straight to multi-codebook tokens across over 600 languages.

Levers and optimisations

Lever What it changes Trade-off
Block size Tokens decided together, and the wait before the first audio (32 frames, 1.28 s, in one system) Bigger blocks mean fewer sequential steps but a longer first wait and weaker left-to-right control Inference
Passes per block How many times blanks are re-predicted More passes give better quality at more compute
Unmasking rule and prior calibration Which blanks to keep each pass (most confident first); calibration subtracts the block's average token distribution from the scores Confidence ranking is fast but biased toward frequent tokens; calibration repairs it at inference time with no architecture change
Early stopping Ends the passes once calibrated confidence is high enough Saves passes; stopping too early leaves errors
Mask-and-replace training Shows the model noisy contexts, not only blanks Lower word error in one study; needs a tuned corruption rate
Reinforcement learning GRPO (scores a group of samples against each other; method in Online RL for speech) tunes the denoising path Better quality on the rewarded metric; the policy is the whole multi-pass trajectory, not one token

Per block, the cost is several model calls instead of one, but those calls produce a whole block, and the latency numbers above show this can still be fast enough for live use. Mask-and-replace is often credited with letting the model fix earlier mistakes; one study finds the gain also holds when every token is frozen once unmasked, so the benefit comes at least partly from training on a noisy context.

What goes wrong

  • Long-tail token bias. A few tokens (silence, common sounds) are far more frequent than the rest, so the model is most confident about them and confidence-based unmasking picks the same safe tokens again and again. Quality drops; subtracting the block's average token distribution before ranking, as prior-calibrated scoring does, fixes it.
  • Tokens chosen together do not see each other. Two tokens unmasked in the same pass are predicted independently, so they can clash at the seam. Inference More passes and fewer tokens per pass reduce this.
  • Early mistakes stick. Once a token is unmasked it is usually fixed, so a confident wrong token constrains every later pass. Mask-and-replace training is one defence.
  • Quality hides in the average. Word error rate and speaker similarity can look fine while some blocks glitch. Check them per block and across seeds. Inference
In the interview, say:

"Block diffusion is autoregressive across blocks and parallel inside them: it unmasks the most confident tokens first, a few passes per block. It keeps streaming and the KV cache while decoding many tokens at once. The known trap is long-tail token bias, where frequent tokens win every confidence ranking, and calibrating against the block's average distribution fixes it."
