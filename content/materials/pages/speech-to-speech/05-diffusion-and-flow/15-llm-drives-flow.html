How an LLM drives a diffusion or flow model

In speech systems that pair a language model with diffusion or flow, the LLM almost never outputs the audio representation itself. It outputs something that conditions the generative model, and that model turns noise into the mel spectrogram or latent. The LLM decides what is said and when; the generative model decides how it sounds.

"Latent" here means the compressed continuous vector per frame from an autoencoder (Continuous latents), not the noisy intermediates of diffusion theory. So the data \( x_1 \) is a mel or a latent, the noise \( x_0 \) has exactly its shape, and a fresh noise sample gives a different but equally valid output.

How it works: two patterns

Pattern A, tokens then flow. The LLM picks discrete semantic tokens with a normal softmax, exactly like text. The flow decoder starts from noise the size of the whole output and generates the mel, conditioned on those tokens (upsampled to its frame rate, for example 25 Hz tokens to a 50 Hz mel), a speaker embedding (a vector that summarises who is speaking; how it is scored is in Measuring speech generation) and the voice prompt's mel; a vocoder then makes audio. The full walk-through is in tokens, then a flow decoder.

Pattern B, hidden state then a per-frame head. The LLM outputs no tokens. Its last-layer hidden vector \( h \) at the current position conditions a small diffusion head, which turns one latent's worth of noise into the next latent; that latent is fed back as the next input (Continuous autoregression). The full life cycle is in end to end.

Some systems skip flow altogether: the LLM predicts codec tokens and a codec decoder makes audio (Multi-codebook patterns, Four routes).

How training works, and whether it is end to end

The deciding difference is the interface. A token choice is a discrete pick, so no gradient can pass through it; a hidden vector is continuous, so gradients flow straight through.

Pattern A: tokens then flow Pattern B: hidden state then head
LLM objective Next-token cross-entropy on semantic tokens No token loss; it learns from the head's diffusion loss arriving through \( h \)
Generator objective Flow-matching loss on the mel, conditioned on the tokens Noise-prediction (or velocity) loss on the true next latent, conditioned on \( h \)
End to end? No in the usual setup: the two objectives are described separately. Inference The decoder is naturally trained on tokens from the tokenizer applied to real audio, not on LLM samples. Yes: the head's loss updates the LLM through \( h \), so the LLM learns to pack into \( h \) what the head needs for the next frame
Frozen parts The speech tokenizer, trained beforehand as a supervised ASR-style model The audio tokenizers, pre-trained and kept frozen; only the LLM and head learn

Levers and optimisations

Lever What it changes Trade-off
Pattern A or B Discrete token interface or continuous hidden-state interface A reuses LLM tooling and token-level RL; B avoids quantisation but needs a sampler per step
Token rate and upsampling (A) How much timing detail the tokens carry before flow fills in acoustics Lower rate is cheaper for the LLM; the flow model must add more detail
Patch size (B) How many frames each LLM step produces Bigger patches mean fewer LLM steps but a harder job for the head

Inference These trade-offs are engineering reasoning rather than measured results. Head size, steps and the frozen tokenizer are covered in end to end.

What goes wrong

  • Inference Pattern A: a decoder trained on clean tokenizer output can meet LLM-sampled tokens it has rarely seen, so errors in the token stream become audible.
  • Inference Pattern B: the LLM trains on true latents but generates from its own samples, so small errors can compound frame to frame; noise scale and guidance are the main controls.
In the interview, say:

"The LLM rarely outputs the audio representation directly. Either it emits semantic tokens and a separately trained flow decoder renders a mel from noise, or it emits a hidden state that conditions a small per-frame diffusion head, trained end to end through that hidden state. The first reuses LLM tooling; the second avoids quantisation at the cost of sampling every step."
