Latency budget, fillers and the cascade baseline

"Under one second" sounds like one number, but it is a sum of stages. Each stage can hide its work behind another if the streams overlap. The craft is overlap: start the next stage on a partial result and cancel if it turns out wrong. A good waiter does the same, writing your order while you finish it and saying "of course" on the way to the kitchen.

The number to manage is time to first audio (TTFA, benchmarked from the gold end of turn in Measuring conversation): here, the wait from the moment the user stops talking to the first sound of the reply at the client. Real-time agent platforms usually carry that audio over WebRTC, the W3C standard for sending live audio, video and data directly between browsers and apps. Inference It is built for small buffers and low delay, which is why such platforms tend to use it.

Inference All latency targets here are illustrative design targets, not measurements. The sourced anchors are that Synthesia describes interactive dialogue as "typically under one second", and that one end-to-end interactive model reports its own total (below).

How it works

In the target design the exchange runs as four overlapping lanes. Partials stream while the user speaks, end of turn fires the tool call, a filler covers the call and the LLM's first token, and the reply starts when text arrives. Later, a user "mm-hm" is ignored and a real barge-in makes the agent yield.

The table sums illustrative targets for the cascade, measured from the end of user speech to first agent audio at the client. The target design replaces the LLM and TTS rows with a filler that plays while the LLM works.

Budget the network as its own line, because the model team cannot shrink it. One end-to-end interactive model reports about 200 ms of response latency on the model side and about 550 ms in total, of which 350 ms is two-way network time. In that system the network is larger than the model, and an avatar that streams video back adds more bytes to the downlink. The levers are servers near users, a jitter buffer sized to the real jitter (a bigger buffer smooths glitches but adds delay), and heavy models kept in one region. Inference The levers are standard practice, not claims from that report.

The cascade baseline is three models plus turn logic run as overlapping streams, and the streaming mechanics are in Streaming inference. The pieces that matter here: the LLM starts on the end-of-turn candidate using the stable transcript, the chunker cuts its tokens at the first clause for a small first TTS chunk, and on barge-in the turn manager cancels the LLM and queued TTS, flushes buffers and truncates the assistant turn to what was played. Its role is fourfold: launch fallback, comparison point on the same benchmark, first generator of synthetic training dialogue, and the path for sessions the speech model cannot serve. Its structural limits are stacked latency, information lost at each text boundary, no recovery from ASR errors, and turn-taking that is an engineered heuristic.

What goes wrong

  • Extra hop latency. The text LLM's first token is the biggest single lever in the budget, and it grows with load. One vendor reports a median first token of about 1.7 s for a large dense model at high throughput, far above a voice-agent target, so tune for latency rather than throughput.
  • Quoted figures that do not compare. "Time to first token", "time to first packet" and "latency between utterances" are different clocks. State where you start and stop, and report p95 and p99 under real concurrency.
  • Cut off mid-thought, or dead air. An aggressive endpoint cuts users off; a conservative one adds dead air. A learned detector shifts the curve and does not remove it.
  • ASR errors and self-interruption. In a cascade the LLM sees only the transcript, so log ASR confidence and let the agent confirm names and numbers. Without echo cancellation the agent hears itself; telephony needs it server-side or a higher barge-in threshold while the agent talks.
In the interview, say:

"I treat a voice agent as overlapping streams. Latency is the overlap: speculative LLM start at end of turn, a small first TTS chunk, a filler over the tool call, and barge-in that cancels everything and truncates context to what was played."
