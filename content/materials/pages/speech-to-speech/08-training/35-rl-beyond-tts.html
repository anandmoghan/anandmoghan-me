RL beyond speech generation

The GRPO loop from the last section does not care what the model produces. Sample several attempts, score them, and move toward the better ones. Only the scorer changes: for recognition it is the transcript, for a voice agent it is whether the task got done.

Each task has a blind spot the reward has to cover. A recogniser rewarded only on text learns to guess fluent words. An agent rewarded only on the final outcome rarely sees a reward at all.

How it works

Recognition with an acoustic judge. A text-only reward compares the output with the reference transcript and never checks the audio. The model can then lean on its language habits and, on poor audio, insert fluent words nobody said (an insertion error). One fix adds a second reward from a frozen frame-by-frame recogniser, trained separately and used only during training, that scores whether the audio supports what the model wrote. On meeting speech, insertion errors fell 28.3% on close microphones and 22.3% on far-field ones, and far-field WER (defined in The speech encoder) fell from 35.89% to 34.71%. At test time only the one trained model runs, with greedy decoding. This is a mechanism shown on one speech model with one judge; do not generalise it.

Streaming recognition with a delay reward. A streaming recogniser must be right and prompt, so one reward scores both: accuracy, plus how late each word is emitted relative to where the word ends in the audio. The study behind it (results in Streaming and latency) measures per-word delay because the structural delay setting is a weak proxy for what a user feels; the delay knobs and how to measure them are in the same section.

Voice agents with per-tool rewards. A voice agent listens, calls tools (see Tools while talking) and speaks. In one audio-only environment, two speech models talk to each other, and the tasks, tools and success checks come unchanged from a text agent benchmark. The characteristic failure is perceptual: the agent picks the right tool but mishears an argument, so the call fails. An outcome-only reward gives little signal, because nearly every group fails the same way, every score is equal and the advantage is zero. A per-turn reward that credits each successful tool call restores the signal, and the trained agent more than doubled task success on an independently built voice benchmark, according to its authors.

A full recipe. A first-party realtime model report combines supervised tuning, a distillation stage and GRPO in executable environments, so the model learns to call tools, read the result and finish the task. It reports task success on a half-duplex adaptation of a voice-agent benchmark rising from 78.4% to 82.0%.

Levers and optimisations

Lever What it changes Trade-off
Frozen acoustic judge as a second reward Penalises words the audio does not support Cuts insertions; the judge is another model to train and trust
Accuracy-delay weighting on a per-word delay metric Where the recogniser sits between exact and fast Lower delay can cost accuracy, so report WER and delay together at each lookahead budget; per-word delay needs word timings from alignment
Per-tool-call (process) reward Gives partial credit inside a task Restores signal; it may reward easy calls over finishing the task Inference
Audio-native environment Whether mishearing can show up as a failure Realistic; slower than text-only simulation Inference
Executable environments with checks Reward is a database or tool outcome, not an opinion Hard to hack; each environment takes work to build Inference

What goes wrong

  • Fluent guesses. A text-only recognition reward cannot tell a guess from a hearing; watch the insertion count, not only WER.
  • Silent groups. When every rollout in a group scores the same, the advantage is zero and the update is empty; track the fraction of such groups.
  • Unsafe actions under pressure. The agent environment reports agents making an unauthorised write and then wrongly believing it helped; include safety checks in the success definition.
In the interview, say:

"The GRPO loop carries over to recognition and agents; only the reward changes. For recognition I add a frozen acoustic judge so the model cannot invent words, and a delay term for streaming. For voice agents I use a per-tool-call reward, because outcome-only reward gives almost no signal."
