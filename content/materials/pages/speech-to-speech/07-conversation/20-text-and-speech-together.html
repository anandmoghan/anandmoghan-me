Producing text and speech at the same time

A person who speaks well usually knows the next few words before the current ones are finished. A voice model can copy that habit. It writes the words as text and voices them a moment later, so the text carries the reasoning and the audio carries the delivery.

The difficulty is rate. Text is slow and audio is fast, so the two streams need a rule for how they line up. Three rules cover most systems: parallel streams with a delay, interleaving in a fixed ratio, and a thinker model that hands off to a talker. A fourth, a small fast talker beside a large slow thinker, gets its own section: Thinking while talking.

How it works

Time-aligned text with padding (the inner-monologue style). The text stream sits on the same frame grid as the audio. A word is one text token but takes several 80 ms frames to say, so most text slots would otherwise be empty. Frames with no new word therefore carry a padding token, and a special token marks the end of the padding before the next word. This keeps the text lane exactly as long as the audio lane, with the same frame index. An illustrative six-frame stretch of the text lane:

Frame 1 2 3 4 5 6
Text lane PAD PAD EPAD "Hello" PAD PAD

The agent is silent in frames 1 and 2, EPAD signals that the next word is about to start, and "Hello" lands on frame 4, after which the model pads while the word is voiced. Most text slots are padding (Conversation clock), so roughly one frame in three carries a real token. The agent's text is predicted first in each frame, then its audio.

Delay as a knob. The offset between the streams is a setting, not an architecture. Delayed streams modelling makes the point cleanly: it uses the same two-stream layout for both recognition and synthesis and only changes which stream is delayed. For recognition the text trails the audio by a couple of seconds, because the model needs to hear ahead before it commits a word. For synthesis the audio trails the text, because the model needs to read ahead before it commits the intonation. A "text and voice at once" model sits between the two: text a little ahead, speech following. The delay always runs from the stream that must wait for more context to the stream that supplies it.

Interleaving ratios. Drop the shared grid and fix an order instead. One example alternates 13 text tokens with 26 speech tokens, a 1:2 ratio. A ratio is not a duration. At 12.5 speech tokens per second, 26 tokens last 2.08 s, so the text runs at 6.25 tokens per second. The speech token rate is what turns the ratio into time.

Thinker and talker. Split the jobs. The thinker is a text LLM that finishes a thought, and the talker is a speech model that reads the thinker's hidden states and produces audio tokens. Because the two are separate models, the thinker can run ahead of the talker. Inference The cost is a hand-off interface, and a lossy one if only text crosses it. Levers and optimisations

Lever What it changes Trade-off
Text-audio delay How far the words run ahead of their voice A longer lead gives planning room and costs latency; the base model randomised it in pretraining and set it to zero in fine-tuning
Padding scheme How text slots map to frames Padding keeps a free time axis; the stream is mostly empty and the model must learn when to place a word
Interleave ratio Share of text against speech tokens More text per speech token front-loads reasoning; fewer text tokens leave the voice less guidance
Chunk read and write sizes How many text states are read before speech tokens are written Larger chunks give smoother prosody; smaller chunks start sooner
Several audio tokens per pass Speech tokens emitted per forward pass A multi-token prediction head speeds decoding; it adds a module to train
Thinker and talker split Who owns content and who owns delivery Thinker can finish early and be swapped; the interface may lose paralinguistic detail

Trade-offs here are engineering reasoning from the sources, not ablations. The one hard constraint: whatever the coupling, the text must be ready before the audio it conditions.

What goes wrong

  • Text and speech drift apart. If the voice runs past its text, the model says something the transcript does not contain. Teams check that the words recovered by an ASR from the audio match the text stream.
  • Ratio mistaken for duration. "13:26" says nothing about seconds until the speech token rate is stated.
  • First-chunk latency read as steady state. The first packet and the chunk that follows are different numbers.
  • Reasoning that waits for the turn to end. A model that reasons in text before speaking adds that reasoning time to every reply. The next section moves the reasoning into the listening window or alongside the speech.
In the interview, say:

"I treat the text-audio offset as a setting. Text a little ahead of the voice gives the model room to think while it speaks. Padding keeps a time axis, interleaving fixes an order, and thinker-talker separates content from delivery. A ratio only becomes a duration through the speech token rate."
