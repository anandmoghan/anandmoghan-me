Turn-taking, backchannels and barge-in

People do not wait for silence before they answer. They predict where the other turn will end, and they start a fraction early. They also murmur "mm-hm" while listening, and they stop talking when someone cuts in. A voice agent that only reacts to silence will always sound a beat late.

Three behaviours need to be told apart. A floor transfer hands the floor over smoothly. A backchannel signals attention and leaves the floor with the speaker. A barge-in takes the floor, and the agent must yield. Getting them right takes four pieces that build on each other: predicting when the user's turn ends, telling a backchannel from a barge-in, cleaning the microphone signal so those decisions can be trusted, and stopping gracefully when the user does take the floor.

How it works

Predicting the end of a turn. Define the floor-transfer offset as the agent's onset minus the user's end:

\[ \Delta = t_{\text{agent onset}} - t_{\text{user end}} \]

On smooth transfers people have a median \( \Delta \) of about \( -151 \) ms, so they begin before the other turn ends. A system that waits for silence can only produce \( \Delta > 0 \), so a negative offset needs prediction. Inference Streaming latency showed the simplest answer, an end-of-turn head inside the recogniser; this section covers the stand-alone detectors.

The self-supervised version is voice-activity projection. Voice activity means who is speaking and who is silent at each moment, read per speaker. The model predicts both speakers' future voice activity from the audio so far, and the labels come free from the recording itself, so nobody annotates turns. It learns where turns tend to end and where a pause is only a breath. Some predictors read the words so far and others the audio. In a duplex model the prediction is folded into generation. A cascade uses a separate detector.

Semantic detectors. Silence length alone cannot tell a hesitation ("I want to book a... hmm") from a finished request, so the newer detectors decide from the partial speech itself, usually without waiting for a transcript. One reads the compact tokens of a neural audio codec and uses a label-delay training scheme that the authors report reduces cut-off errors. Another predicts the time until the user's next speech onset, which can be computed from timestamps and so needs no extra annotation. A confidence gate on a "continue" or "stop" decision makes the agent commit only when it is sure. Each is tested on its own benchmark, so there is no single ranking; newer benchmarks frame turn-taking as a structured decision with controlled context. Backchannel against barge-in. Once the agent is talking, any user sound is one of these two. The difference is intent: one wants the agent to continue, the other wants the floor. Short, quiet and context-fitting sounds ("right", "uh-huh") look like backchannels. Inference A model that cannot tell them apart stops at every "mm-hm".

Keeping the signal clean. That decision is only as good as the microphone signal. The microphone hears the agent's own voice from the speaker, so without a fix the agent can mistake itself for the user and interrupt itself. The usual fix is acoustic echo cancellation (AEC), which takes the playback signal as a reference and subtracts it from the microphone input; a neural AEC can be small enough to run on a phone. Other voices are a second problem, since a TV or a bystander can trigger a false barge-in. One approach folds voice-activity detection, turn-taking, speaker recognition and recognition into a single front-end model, anchored to the user by a short reference clip of their voice (target-speaker conditioning). A third job is a running transcript of the user, which duplex models do not normally produce; a lightweight transcription head beside the agent's text output adds one with few extra parameters. Stopping, and fixing memory. Stop latency is the time from the user's onset to the last audible agent sample:

\[ L_{\text{stop}} = t_{\text{last audible agent sample}} - t_{\text{user onset}} \]

On a barge-in the agent must also repair its own memory. Speech is generated faster than it plays: the model produces audio in bursts ahead of the speaker, and the unplayed part waits in a playback buffer. When the user cuts in, the model has "said" far more than the user heard. The client reports the playback position back, and the context keeps only the words actually played. Otherwise the agent believes it said a sentence the user never heard. See System design for the full barge-in sequence.

Levers and optimisations

Lever What it changes Trade-off
End-of-turn threshold How confident the detector must be before the agent starts Low threshold gives quick replies and cuts users off; high threshold is safe and adds dead air
Semantic detector Whether the end-of-turn decision reads meaning, not only silence Fewer cut-offs on mid-thought pauses; extra compute per window and a confidence threshold to tune
Barge-in threshold, and a stricter one while the agent speaks How much user speech is needed to yield Low yields fast and stops at coughs or echo; high ignores real interruptions
Resume window Whether the agent resumes if no transcript follows an interruption Recovers from false yields; repeats or stalls if set badly
Action channel One token per step: listen, respond, interrupt, backchannel Makes the decision learnable and measurable; needs labelled interaction data
Target-speaker prompt A short reference clip of the user to lock onto their voice Ignores background talkers; needs a clean clip at the start and fails if the user changes
Echo reference path Playback signal as an extra input Removes self-triggering; adds a synchronisation requirement

The two thresholds are the same curve seen from two sides: a learned detector moves the curve and does not remove it. Report false-cutoff rate at a fixed latency budget, or latency at a fixed false-cutoff rate, rather than one threshold.

What goes wrong

  • Backchannel read as barge-in. The agent stops mid-sentence at "mm-hm". A recent survey calls it the most-cited failure in user feedback. Track the false-yield rate per minute.
  • Premature takeover. The agent answers during a mid-thought pause. Track the false-cutoff rate at a latency budget.
  • Passing for the wrong reason. A barge-in test run on audio with echo can pass because the agent heard itself. Measure stop latency on echo-cancelled output.
  • One metric optimised. An agent that stops at every cough has excellent stop latency and a terrible false-yield rate. Always report both.
  • Memory of unplayed speech. Skipping truncation leaves words in context that were never heard.
  • Models that rarely backchannel. User studies find audio foundation models miss when to speak, interrupt too aggressively and rarely backchannel.
In the interview, say:

"Humans start a median of about 150 ms before the other turn ends, so the target offset is negative and needs prediction. The key failure is a backchannel treated as a barge-in. I would report stop latency on echo-cancelled output together with false-yield rate at one operating point."
