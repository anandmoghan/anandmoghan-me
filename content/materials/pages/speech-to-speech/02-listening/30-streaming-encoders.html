Streaming encoders

A bidirectional encoder is a proofreader who reads the whole page before marking any line. The vector for frame 3 depends on frame 300, and every new frame can change every old output. Live speech cannot work that way.

A streaming encoder is a live captioner. It uses what it has heard, plus at most a short peek ahead, so earlier outputs stay put and can be cached. The whole game is restricting attention without losing accuracy.

How it works

Whisper as shipped does not stream, for two reasons. It takes a fixed 30 s window, and streaming wrappers pad every buffer to that window, so each partial result pays for 30 s. And its attention is bidirectional, so every frame sees later audio.

The fix is a mask on the attention matrix. A chunk mask lets every frame read its own chunk and all earlier chunks, but never later ones. Earlier chunks never change, so their work can be stored and reused. In attention, each frame produces a query (what it is looking for), a key (how it can be matched) and a value (what it hands over when matched), and it mixes the values of the frames whose keys match its query best. The KV cache stores the keys and values of finished chunks, so a new chunk computes only its own and reads the rest from memory instead of re-running the whole history. The price is memory for each live stream. A block window is stricter still: each frame reads only its own block.

Five families apply this idea, at different cost. The newest two start from a blank page and no longer inherit Whisper's design.

Inference The last family is where the field is moving. Retrofitting Whisper is still useful when you already ship it, but an encoder trained to stream removes the fixed window, the padding cost and most of the wrapper machinery at once. Mimi, the codec in Moshi, shows the principle at its simplest: all its convolutions are causal, so it streams by construction.

Levers and optimisations

Lever What it changes Trade-off
Chunk or window size How much audio each step sees (40 to 300 ms in CarelessWhisper; 1 to 8 s windows in AuT) Larger chunks read more context and cost more latency. Streaming at 2 s chunks cost Qwen3-ASR about 0.6 average WER against offline for the 1.7B model.
Causal against bidirectional Whether a frame may read later audio Causal outputs never change and can be cached; bidirectional sees more context per frame. See look-ahead.
Wrapper, fine-tune or replace How much you retrain Wrappers need no training but cost latency; LoRA is cheap; a new encoder gets both modes but needs a from-scratch run.
Delay knob, dynamic chunk training Voxtral Realtime samples a delay from 80 to 2400 ms in training; a U2-style variant samples chunk sizes of 0.1 to 1.0 s One model serves several latency budgets, but training must cover the whole range and a shorter setting costs accuracy.

What goes wrong

  • Padding and mismatch. A wrapper pays for a 30 s window on every partial and re-encodes the same audio repeatedly. The U2 authors add that it leaves a train/test mismatch, because the model was trained on full 30 s windows and is run on partial buffers.
  • Words cut at chunk boundaries. A chunk can end mid-word; Simul-Whisper adds a truncation detector for exactly this.
  • Hallucination on silence. A streaming window is often mostly silence. Whisper's long-form decoding skips windows above a no-speech threshold (0.6), and a VAD filter in front of the model (see What a speech encoder does) serves the same purpose.
  • An accuracy gap. Streaming is worse than offline for the same model (2.69 against 3.33 average WER for Qwen3-ASR 1.7B), so budget for it. Qwen-Audio-3.0-ASR shows the same shape at 400 ms of algorithmic latency: 9.24% against 8.03% error on Chinese and 13.38% against 11.78% on English.

Model-by-model detail: Making the Whisper encoder stream and Streaming audio encoders beyond Whisper.

In the interview, say:

Whisper streams in three ways: wrap it and pay for re-encoding, fine-tune it causal with a chunk mask and an encoder cache, or replace the encoder. Wrappers cost latency, causal fine-tuning gets sub-second latency, and a streaming encoder trained from scratch, like AuT or Voxtral Realtime, costs a full run but serves streaming and offline from one model, with the delay as a dial.
