How audio meets text inside an LLM

An LLM reads one sequence of positions. In a speech LLM, some positions hold audio vectors and some hold text tokens. The layout of those positions decides when text can come out, whether the model can stream, and what alignment data training needs.

Picture three transcriptionists. One listens to the whole recording, then types (prefix). One types after every few seconds of audio and signals the end of each batch (chunk-interleaved). One has a metronome and, on every tick, writes either nothing or a few words (per-frame blank). Models differ mainly in which of these habits they copy.

How it works

Two ideas from classic speech recognition recur below. Connectionist temporal classification (CTC) is a loss in which the model outputs, at every audio frame, either a label (a letter or word piece) or a blank meaning "nothing new here". Collapse repeated labels, drop the blanks, and the text is left. Because every frame carries a label or a blank, a CTC model can say which frame each word fell in; run on audio whose transcript is known (forced alignment), it yields word timings, and several layouts below get their training targets this way.

A transducer is the second idea: an ASR model with an audio encoder, a prediction network that reads the text written so far, and a joint network. The joint network combines the current audio vector with the current text-history vector and scores every possible next token plus blank, where blank means "not yet, give me the next audio frame".

Six layouts cover the field.

  1. Prefix (soft prompt). Projected audio comes first, then a task prompt, then text is generated. Text starts only after all audio is in, so this does not stream, but it needs no alignment. Qwen2-Audio and Voxtral work this way.
  2. Chunk-interleaved. Each audio chunk is followed by that chunk's text and an end-of-chunk token (EOC). SpeechLLM-XL uses 1.28 s chunks. Training needs each token's end time, from reference alignments or CTC forced alignment.
  3. Per-frame blank (wait token). After each audio embedding (every 240 ms in Speech ReaLLM) the model emits words until it emits BLANK, so a frame can yield zero, one or several words. Targets come from an external CTC "alignment teacher", a separate model whose frame-level timings say where each word belongs.
  4. Transducer with an LLM predictor. Audio does not enter the LLM input at all; the LLM plays the prediction network. Transducer-Llama scores the non-blank choice by combining the acoustic and language scores:
\[ P_{nb} = (1 - P_b)\,\operatorname{softmax}\big(\log P_{ac} + \log P_{ilm}\big) \]

Here \( P_b \) is the blank probability, \( P_{ac} \) the acoustic score and \( P_{ilm} \) the internal language-model score, which the LLM replaces after transducer training. A token wins only if the audio and the language model both like it; adding logs is the same as multiplying probabilities without the tiny numbers a long product produces. The softmax renormalises the sum to 1, and \( 1 - P_b \) reserves the share left once blank has taken its part. If the audio sounds equally like "their" and "there" but the text so far is "over", the language score tips the choice to "there". The LLM stays frozen apart from new embedding and output layers for the ASR vocabulary.

  1. Summed time-aligned streams. Every stream gets its own embedding table, and at each step the embeddings are added into one vector. The text stream holds words with PAD between them; PAD is about 65% of the text tokens in English conversation in Moshi. For ASR, DSM delays the text stream, 2.5 s by default, and Voxtral Realtime feeds the delay to the decoder as an input so one model can run at several delays. A duplex dialogue model can also transcribe the user this way, with a lightweight ASR head beside the agent's text head on the same backbone. See Conversation.
  2. Hybrid continuous plus discrete input. Kimi-Audio adds downsampled continuous Whisper features to the embedding of a discrete semantic token at each 12.5 Hz step. It changes the audio input, not the text layout.

Levers and optimisations

Lever What it changes Trade-off
Layout When text can appear Prefix is simplest but waits for the whole utterance. Streaming layouts need aligned training data.
Alignment source Reference timestamps, CTC forced alignment, external CTC teacher Extra pipeline. Inference Bad alignments become bad training targets.
Hybrid input Continuous features plus semantic tokens per step Recovers detail lost by pooling, at the cost of a more complex input path.
Waiting-step cost A factorized variant of DSM predicts "wait" with a separate yes/no probability Skips the full vocabulary softmax on the many steps where the model stays quiet.

Chunk length, right context and text delay are the latency dials of these layouts; their numbers are in Streaming ASR families.

What goes wrong

  • Silence dominates. With PAD at about 65% of text tokens, the model must learn to stay quiet most steps, and in Speech ReaLLM the response after an embedding is often empty. A full vocabulary softmax on every one of those steps is waste.
  • Weak alignment. Chunk and frame layouts inherit the errors of the aligner that built their targets, and a word that straddles a chunk boundary lands in one chunk or the other. Inference
  • No partials from a prefix model. An agent that must start thinking while the user speaks needs a streaming layout. Inference

Model-by-model detail: How encoder audio and ASR text meet inside the LLM.

In the interview, say:

Audio and text share one sequence, and the layout sets latency: a prefix waits for the whole utterance, while streaming models interleave chunks with an end-of-chunk token, emit a blank per frame, run a transducer, or sum time-aligned streams. The cost is alignment, so for a voice agent I would pick chunk interleaving or time-aligned streams to get text while the user is still speaking.
